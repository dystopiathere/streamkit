# StreamKit

Платформа для стримеров: конструктор виджетов-оповещений, агрегация донат-событий,
дашборд аналитики подключённых площадок. Монетизируемый продукт под аудиторию РФ.

## Состояние

Готов вертикальный срез: регистрация → виджет → ссылка для OBS → событие →
оповещение на экране. Проверен сквозным тестом в браузере.

Готова аналитика площадок: подключение канала по OAuth, сбор метрик по
расписанию, графики зрителей и подписчиков в дашборде. YouTube проверен на живом
канале, Twitch написан по спецификации и ждёт регистрации приложения.

Сознательно **не** сделано (решение принято на этапе планирования):
- собственный приём платежей — платформа не платёжный агент, донаты приходят
  событиями из внешних сервисов;
- приватные WebRTC-комнаты (LiveKit) — отдельный этап.

## Устройство

```
apps/
  api/       NestJS: HTTP, WebSocket и фоновый процесс (worker.ts) — один код, две команды
  web/       React + Vite: дашборд стримера
  overlay/   React + Vite: страница для браузер-сорса OBS, отдельное приложение
packages/
  contracts/ Zod-схемы — единственный источник правды для данных между приложениями
  ui/        Рендерер виджета и очередь показа: общие для дашборда и overlay
  config/    Пресеты tsconfig
e2e/         Playwright: сквозные сценарии по собранным приложениям
infra/docker/ Dockerfile'ы и compose
docs/        ADR и юридический блок
```

В каждой папке есть свой `CLAUDE.md` с деталями — читайте его перед правками.

## Технологии

TypeScript (strict) везде. NestJS 11, Prisma 6 + PostgreSQL 17, Redis 7,
Socket.IO, React 19, Vite 7, Tailwind 4, Zod 3, Vitest 3, Playwright,
pnpm workspaces + Turborepo, Docker.

## Правила, общие для всего репозитория

1. **Деньги — целые минорные единицы** (`amountMinor` + `currency`). Ни одного
   `float` для сумм ни на каком этапе, включая промежуточные вычисления.
2. **Контракт данных живёт в `packages/contracts`.** Если структура пересекает
   границу приложения — её схема там, а не продублирована в двух местах.
3. **Секреты в БД — только в виде хэша или шифротекста.** Токены сессий и ссылок
   хэшируются (`TOKEN_HASH_PEPPER`), токены внешних сервисов и TOTP шифруются
   AES-256-GCM (`ENCRYPTION_KEY`). Ключи РАЗНЫЕ и ротируются независимо.
4. **Всё закрыто по умолчанию.** Guard включён глобально; открыть эндпоинт можно
   только явным `@Public()`.
5. **Чужой объект — 404, не 403.** Разные коды ответа позволяют перебирать
   существующие идентификаторы.
6. **Пользовательский текст рендерится как текст.** `dangerouslySetInnerHTML` в
   рендерерах виджетов запрещён: overlay открыт по публичной ссылке.
7. **Комментарии объясняют «почему», а не «что».** Особенно там, где решение
   выглядит странно (см. ниже раздел про грабли).

## Команды

```bash
docker compose -f infra/docker/compose.dev.yml --env-file .env up -d  # базы
pnpm db:migrate        # миграции
pnpm dev               # все приложения в режиме разработки
pnpm test              # юнит-тесты всех пакетов
pnpm --filter @streamkit/api test:int   # интеграционные (нужны БД и Redis)
pnpm --filter @streamkit/e2e test       # сквозные (нужна сборка: pnpm build)
```

Установка зависимостей на машине владельца требует явного прокси:
`pnpm install --config.proxy=http://127.0.0.1:10808 --config.https-proxy=http://127.0.0.1:10808`

## Грабли, на которые уже наступили

Каждая из них стоила отладки — не наступайте повторно.

- **`enableReadyCheck` на Redis-подписчике.** ioredis выполняет `INFO` при
  ready-check, а в режиме подписки обычные команды запрещены: клиент не доходит
  до `ready` и теряет подписку. Симптом: `publish` возвращает 0 получателей,
  ошибок нет, события не доходят. См. `apps/api/src/common/redis/redis.module.ts`.
- **`ConfigModule` отдаёт приоритет файлу `.env` над переменными процесса.**
  Из-за этого тестовые значения молча перетирались боевыми. В тестовом режиме
  файл игнорируется, см. `apps/api/src/config/config.module.ts`.
- **`VITE_API_URL` — это origin, без `/api`.** HTTP-база и origin сокета — разные
  значения, они разведены в `apps/web/src/lib/config.ts`.
- **Prisma на Windows не подключается к `localhost`**: резолвит в `::1`, а
  контейнер опубликован на IPv4. В `DATABASE_URL` нужен `127.0.0.1`.
- **React Testing Library без `globals: true` не чистит DOM** между тестами, и
  соседние тесты находят чужую разметку.
- **Квота YouTube Data API выдаётся на ПРОЕКТ, а не на пользователя.** 10 000
  единиц в сутки делятся между всеми стримерами платформы; остаток в ответах не
  приходит. Считаем сами, см. `docs/adr/0007`.
- **Vitest не читает `vite.config.ts`, если рядом есть свой конфиг.** Алиас
  `@/` приходится объявлять в обоих, иначе тесты падают на «Failed to resolve
  import», и это выглядит как поломка теста, а не конфигурации.
- **Расписание `@Cron` живёт в каждой реплике воркера.** Задача, которая обязана
  выполниться один раз на кластер, оборачивается в `RedisLock.withLock`
  (`src/common/redis/lock.service.ts`).
- **Лимиты запросов без общего хранилища считаются в памяти процесса.** При
  нескольких инстансах API лимит молча умножается на их число; счётчики живут в
  Redis.
