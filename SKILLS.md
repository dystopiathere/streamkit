# Навыки и плагины, полезные для StreamKit

Список доступных в этой среде скиллов, отобранных под задачи проекта. Полный
каталог гораздо шире — здесь только то, что имеет смысл применять здесь, с
пометкой когда именно.

Вызов: `/имя-скилла` или через инструмент Skill.

## Постоянно в работе

| Скилл | Когда применять |
|---|---|
| `code-review` | Перед каждым вливанием изменений. `code-review ultra` — многоагентный разбор ветки в облаке, запускается пользователем |
| `security-review` | После правок в аутентификации, вебхуках, шифровании, при подготовке платёжного модуля |
| `engineering:testing-strategy` | Когда решаем, что покрывать юнит-, что feature-, а что сквозным тестом |
| `engineering:debug` | Систематический разбор плавающих ошибок — вроде истории с потерянной подпиской Redis |
| `simplify` | Чистка после серии быстрых правок: дубли, лишние абстракции |
| `update-config` | Настройка хуков и разрешений Claude Code в `settings.json` |

## Фронтенд и интерфейс

| Скилл | Когда применять |
|---|---|
| `impeccable` | Общая доработка интерфейса: иерархия, доступность, состояния, адаптив |
| `emil-design-eng` | Полировка деталей: тайминги, фокус, микровзаимодействия |
| `animate` | Анимации оповещений и переходов — ровно наш случай с виджетами |
| `animation-vocabulary` | Когда нужно назвать нужный эффект, а не описывать его словами |
| `apple-design` | Жесты и пружинные анимации, если делать перетаскивание в редакторе раскладки |
| `ask-sonner` | Уведомления в дашборде (библиотека уже подключена) |
| `dataviz` | Графики аналитики. Читать ДО написания кода графиков; палитру проверять его валидатором, а не на глаз |
| `modern-web-guidance:modern-web-guidance` | Актуальные возможности платформы вместо устаревших рецептов |

## Архитектура и продукт

| Скилл | Когда применять |
|---|---|
| `engineering:architecture` | Перед вводом WebRTC-комнат и платёжного контура |
| `engineering:system-design` | Проектирование масштабирования: шардирование сокетов, очереди |
| `engineering:tech-debt` | Инвентаризация долга (см. «Известные ограничения» в CLAUDE.md) |
| `product-management:write-spec` | Спецификация перед крупной фичей |
| `operations:runbook` | Инструкции дежурного: что делать при отказе Redis, БД, площадки |
| `operations:risk-assessment` | Оценка рисков перед запуском приёма платежей |

## Юридическое и соответствие

| Скилл | Когда применять |
|---|---|
| `legal:compliance-check` | Сверка реализованного с требованиями 152-ФЗ |
| `legal:review-contract` | Разбор оферты и договоров с платёжными провайдерами |
| `legal:legal-risk-assessment` | Оценка рисков агентской схемы приёма донатов |

Ни один из них не заменяет живого юриста. Тексты в `apps/web/public/legal` —
черновики и требуют проверки перед публикацией.

## Подключаемые интеграции (требуют авторизации)

Эти серверы настроены, но не авторизованы в текущей сессии. Авторизация — через
настройки коннекторов claude.ai или `claude mcp` в интерактивной сессии.

| Сервер | Зачем может пригодиться |
|---|---|
| `github` | Работа с PR, issues, CI прямо из сессии |
| `datadog`, `pagerduty` | Мониторинг и дежурства, когда проект дойдёт до прода |
| `linear`, `notion`, `asana` | Ведение задач |
| `figma` | Макеты дашборда |
| `prisma:Prisma-Remote` | Управление базой через Prisma Platform |

## Чем пользовались в этом проекте

- `code-review` — дважды. Перед веткой аналитики: 15 подтверждённых замечаний.
  Перед веткой виджетов: 9, из них два делали аналитику YouTube
  самоотключающейся — 403 при исчерпании квоты трактовался как мёртвый токен.
  Все исправлены.
- `code-review` в третий раз — по слитому этапу чата: шесть находок. Главная:
  каналы после двадцатого не подключались к чату никогда — Twitch молча
  отбрасывает JOIN сверх лимита. Ещё одна находка оказалась утечкой данных между
  пользователями: выход не чистил кэш запросов, и баннер cookie принимал
  журнал согласий предыдущего человека за согласие нового.
- Уязвимость, которую не нашёл ни один скилл: CSP и `X-Frame-Options` не
  доходили до HTML-страниц из-за правила наследования `add_header` в nginx.
  Нашлась при чтении инфраструктуры под комнаты и подтверждена `curl -I` на
  старом и новом конфиге.
- `security-review` — со второго раза запустился (у репозитория появился
  удалённый), но получил пустой диф: ветка была слита в `main`. Разбор снова
  выполнен вручную по его критериям, на этот раз по диапазону коммитов.
  Эксплуатируемых уязвимостей в OAuth-контуре и аналитике не нашлось.
- `artifact-design`, `artifact-diagramming` — отчёт о сборке.
- `dataviz` — графики аналитики. Его валидатор палитры отбраковал очевидный на
  вид выбор: синий из стандартной палитры рядом с фиолетовым акцентом приложения
  даёт ΔE 0.9 для дейтеранопии, то есть для такого зрителя это один цвет.
  Заодно правило «никаких двух осей» развело зрителей и подписчиков по разным
  графикам, а не по двум шкалам одного.
- Из встроенного инструментария применялись обычные средства: файловые операции,
  Bash, Docker, запуск тестов.

## Как выбирать

1. Задача про внешний вид и ощущения → `impeccable`, `emil-design-eng`, `animate`.
2. Задача про безопасность и деньги → `security-review`, `legal:*`, и только
   потом код.
3. Задача про «почему не работает» → `engineering:debug`, а не перебор гипотез.
4. Задача про графики → сначала `dataviz`, потом код.
