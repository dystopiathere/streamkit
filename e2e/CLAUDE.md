# @streamkit/e2e

## Назначение
Сквозные сценарии в настоящем браузере. Проверяют то, что недоступно юнит- и
feature-тестам: что собранный оверлей действительно устанавливает соединение и
отрисовывает событие, прошедшее через Redis и сокет.

## Технологии
Playwright, Chromium.

## Ключевое решение

Тесты гоняются по **собранным** приложениям, а не по dev-серверам. Переменные
`VITE_*` вшиваются в бандл при сборке, и проверять надо именно тот артефакт,
который поедет в прод — иначе ошибка конфигурации сборки обнаружится после
деплоя. Playwright сам поднимает серверы: API, фальшивые ЮKassa, DonationAlerts, Twitch и YouTube, дашборд,
оверлей и админку.

## Правила

- Один воркер: тесты делят одну базу, параллельный прогон сделает результат
  случайным.
- Уникальные email на каждый прогон (`Date.now()`): база между прогонами не
  чистится.
- **Браузер русский** (`locale: 'ru-RU'` в `playwright.config.ts`): язык
  дашборда берётся из браузера, а у Playwright по умолчанию en-US. Английский
  интерфейс — `english.spec.ts`, через `?lang=en`.
- Селекторы — по роли и тексту, как их видит пользователь. `data-testid`
  оставлен только для карточки оповещения, у которой нет осмысленной роли.
- **Сохранение настроек виджета — `Сохранить настройки`** (подпись для диктора
  кнопки «Сохранить» в правой колонке редактора): рядом есть «Сохранить»
  стартовой суммы цели. Поля — в разделах редактора: перед полем щёлкнуть его
  вкладку (`getByRole('tab', { name: 'Текст', exact: true })`). Вкладка
  подписывает панель раздела, поэтому `getByLabel('Комната')` находит и
  панель — поле ищут по роли (`combobox`).
- Строгий режим Playwright не прощает неоднозначных селекторов: «тест» находится
  и в бейдже, и внутри «Тестовый зритель» — нужен `{ exact: true }`.
- **Подвал стоит на каждой странице, и в нём карта сайта**, а в дашборде — ещё
  и все разделы кабинета и профиля. Ссылку шапки ищут внутри её `<nav>`:
  `mainNav(page)` в `tests/navigation.ts` (`exact`: «Разделы» совпадает и с
  «Разделами профиля»), на главной — `getByRole('navigation', { name: 'Разделы
  главной' })`. Разделы профиля — через имя в шапке: `openProfileSection(page,
  'Тариф')`; выход — `logout(page)`.
- **Восстановление пароля по письму в прогоне не проходится**: API работает в
  production-режиме, а там письма уходят только по TLS, поддельного SMTP с TLS
  нет. Сервер закрыт `password.int.test.ts`, страницы — ручной проверкой через
  mailpit из `compose.dev.yml` (письма — на http://localhost:8025). Смену пароля,
  меню профиля и карту кабинета проверяет `account.spec.ts`.
- **Локально тесты переиспользуют уже запущенные серверы** (`reuseExistingServer`),
  а у `pnpm dev` боевой лимит: десять запросов к `/auth` в минуту с IP. Полный
  прогон его исчерпывает, и тест, перезагрузивший страницу, вылетает на форму
  входа — это 429 на обновлении токена, а не поломка сессии. Либо запускайте
  API с `THROTTLE_AUTH_LIMIT=100000`, либо гоняйте файлы тестов по одному с
  перерывом в минуту. В CI лимит поднимает `playwright.config.ts`.
- **ЮKassa — фальшивая** (`fake-yookassa.mjs`, четвёртый сервер Playwright):
  создание и статус платежа, списание по сохранённому способу и страница
  подтверждения, которая «оплачивает», шлёт уведомление в API и возвращает
  браузер. Стримерам в сценариях комнат тариф оформляется через API
  (`subscribe` в `rooms.spec.ts`), если оплата на сервере настроена.
- **Админка** (`admin.spec.ts`) — пятый сервер Playwright, `admin preview` на
  :5175. Сотрудник заводится как на проде: второй фактор через API дашборда
  (`otplib`), роль — скриптом `apps/api/dist/scripts/grant-role.js`, поэтому
  нужна сборка API.
- **Двухфакторный вход** (`two-factor.spec.ts`) включается и выключается
  через интерфейс дашборда, код считает `otplib` по ключу со страницы. Короткий
  путь через API в `admin.spec.ts` этот сценарий не заменяет.
- **DonationAlerts — фальшивый** (`fake-donationalerts.mjs`): страница входа сразу
  возвращает браузер с кодом, есть обмен кода и профиль. Сокета нет: воркер в
  прогоне не запускается, его путь — в `donation-sources.int.test.ts`. Этот
  сценарий — единственная проверка OAuth в настоящем браузере (cookie state на
  переходе с чужого домена).
- **Twitch — фальшивый** (`fake-twitch.mjs`, порт `FAKE_TWITCH_PORT`, 3097):
  вход, обмен кода, пользователь и канал Helix. Каждый вход выдаёт НОВЫЙ канал
  `e2e_streamer_N`, поэтому логин тест не задаёт, а читает с карточки
  (`connectTwitch` в `tests/platforms.ts`) — так же проверяется и
  переподключение другого аккаунта. EventSub в прогоне нет — нет воркера; его
  путь закрыт `twitch-events.int.test.ts`.
- **YouTube — фальшивый** (`fake-youtube.mjs`, порт `FAKE_YOUTUBE_PORT`, 3096):
  вход Google, обмен кода и `channels.list`. Каждый вход — новый канал
  `UCe2e_yt_…N`; `connectYouTube` возвращает его id и название. Потока чата
  `streamList` в прогоне нет — его путь закрыт `youtube-chat.int.test.ts`.
  Чат и виджет чата без подключённой площадки не работают, так что сценарии
  чата начинаются с `connectTwitch` или `connectYouTube`.
- **Окно эфира** (`stream.spec.ts`): чат кладётся в шину напрямую, как в
  сценарии чата оверлея, — воркера в прогоне нет. Площадки с зрителями и
  временем эфира закрыты интеграционным тестом: снимки пишет опрос, а его в
  прогоне тоже нет.
- **Стенд рядом с `pnpm dev`**: `.env` не разбирается `source` в bash, окружение
  API проще собрать скриптом на node. LiveKit из `compose.dev.yml` шлёт вебхуки
  на `:3000`, поэтому на стенде падает сценарий «гость, удалённый с отзывом
  ссылки…» — его выгоняет вебхук. Это не поломка.
- **Публичная часть сайта** (`public-site.spec.ts`) — то, что проверяет ЮKassa:
  цены, получение услуги, оплата, реквизиты и оферта с подставленными данными.
  Реквизиты — выдуманные, из `playwright.config.ts`.
- **Рядом с запущенным `pnpm dev`** его API не знает про фальшивую ЮKassa, и
  сценарий оплаты пропускается (в CI пропуск — падение). Отдельный стенд — на
  соседних портах: `E2E_WEB_URL`, `E2E_API_URL`, `E2E_OVERLAY_URL`,
  `E2E_ADMIN_URL`, `FAKE_YOOKASSA_PORT`, `FAKE_TWITCH_PORT`, `FAKE_YOUTUBE_PORT`. Дашборд, оверлей и админка для него
  собираются с `VITE_API_URL` своего API — админка из `pnpm dev` ходит в API
  разработки, и сценарий админки с ней упадёт. API запускается из каталога без
  `.env`: иначе файл перетрёт порт.
  `pnpm build` при этом не запускать — он роняет `pnpm dev` (грабли в CLAUDE.md).

## Запуск

Собирать — с `VITE_API_URL`, как в CI. Vite не читает корневой `.env`, и без
переменной HTTP дашборда идёт через прокси `vite preview`, а сокет — в сам
preview, где socket.io нет: падает только сценарий окна эфира, и выглядит это как
поломка чата.

```bash
VITE_API_URL=http://localhost:3000 pnpm build   # обязательно: тесты идут по dist
pnpm --filter @streamkit/e2e test:e2e
pnpm --filter @streamkit/e2e test:e2e:ui   # интерактивный режим
```

Нужны запущенные PostgreSQL и Redis и накатанные миграции.
