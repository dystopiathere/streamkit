# 0012. Прод в Yandex Cloud: две ВМ с Compose, управляемые базы, выкатка кнопкой

Дата: 2026-09-15. Статус: принято.

## Контекст

ADR 0004 выбрал российское облако и Docker без привязки к сервисам конкретного
облака. Владелец выбрал Yandex Cloud и домен stream-kit.ru, а из вариантов —
ВМ с Docker Compose, облако в Terraform и выкатку вручную из GitHub Actions.

До этого в репозитории были только образы и `compose.yml` для одной машины.
Сверка его с продом нашла три поломки, которые проявились бы на первой выкатке:

- у воркера в `compose.yml` не было переменных ЮKassa и площадок — продления
  подписки не списывались бы, а токены площадок не обновлялись, и всё молча;
- миграции запускались `npx prisma migrate deploy`, но npx удалён из образа, а
  CLI Prisma — dev-зависимость и в рантайм не попадает;
- `VITE_API_URL` в образе статики по умолчанию был `/api`, а клиент дописывает
  префикс сам: собранный без аргумента дашборд ходил на `/api/api`.

## 1. ВМ с Compose, а не Managed Kubernetes

Один API, один воркер и две статики умещаются на одной ВМ с запасом. Kubernetes
дал бы реплики и бесшовные выкатки ценой отдельного кластера, балансировщика и
знаний, которых у проекта на старте нет. Цена выбора — несколько секунд простоя
API на выкатке и ручное масштабирование.

LiveKit — на своей ВМ при любом выборе: медиа по UDP, TURN на 443 и адрес узла,
который сообщается браузерам. На одном адресе с Caddy TURN на 443 не помещается.

## 2. Управляемые PostgreSQL и Valkey, а не контейнеры

Резервные копии, обновления и восстановление после отказа диска — работа, от
которой управляемые базы избавляют. Обе без публичного адреса, доступ только из
группы безопасности ВМ приложений, соединения по TLS с проверкой сертификата:
корневой сертификат Yandex Cloud приезжает на ВМ при создании, приложение
добавляет его через `NODE_EXTRA_CA_CERTS`.

Valkey вместо Redis — это то, что Yandex Cloud сейчас предлагает под управлением.
Приложению нужны команды, pub/sub и блокировки, Valkey держит всё это.

## 3. Секреты в Lockbox, читает их ВМ

Секреты не лежат ни в GitHub, ни в образах, ни в репозитории. ВМ получает токен
своего сервисного аккаунта из метаданных и на каждой выкатке собирает `.env` из
Lockbox. Секрета три — по тому, кто их заводит и кто читает: сгенерированные
Terraform для приложения, ключи LiveKit (читают обе ВМ) и заводимые владельцем
(ЮKassa, площадки, реквизиты — Terraform создаёт только пустой секрет).

Честно о границах: сгенерированные секреты лежат в состоянии Terraform, поэтому
состояние — в закрытом бакете. И любой с оболочкой на ВМ получит тот же токен:
доступ к серверу — это доступ к секретам. Ключ выкатки поэтому хранится в
окружении `production` на GitHub, а пользователь `deploy` в группе docker
по сути равен root, и считать его ограниченным нельзя.

## 4. Выпуск и выкатка — разные шаги

Образы собираются автоматически после зелёного CI на `main`, из того коммита,
который проверил CI, с тегом его полного sha. Выкатка — ручной запуск workflow с
этим тегом: слияние PR не должно само менять прод и накатывать миграции.

Выкатка проверяет, что тег — sha из `main` и образы опубликованы; файлы compose и
скрипты берёт из того же коммита, что и образы. На ВМ: окружение из Lockbox,
скачивание образов, миграции отдельным образом, пересоздание, ожидание
`/api/readyz`, проверка снаружи по TLS, CSP и реквизитам. Откат — тот же
workflow с предыдущим тегом.

**Отвергнуто: выкатка на каждый пуш в `main`.** Быстрее, но миграции уезжали бы
в прод слиянием PR, и остановить выкатку можно было бы только откатом.

## 5. Сторонние образы — из своего реестра

Caddy, LiveKit и lego копируются в Container Registry при выпуске. ВМ тянут
образы только из `cr.yandex` и не зависят от доступности и лимитов Docker Hub в
момент выкатки или перезапуска.

## 6. Вебхуки LiveKit — по внутреннему адресу

LiveKit шлёт `participant_joined` в API на внутренний адрес ВМ приложений, а не
на `https://api.stream-kit.ru`. Проверка входа в комнату (ADR 0010) не должна
зависеть от сертификатов и публичного DNS: без вебхука отозванный гость входит
обратно, и ничего об этом не сообщает.

## Последствия

- Облако поднимается `terraform apply`, прод обновляется кнопкой, откат —
  тоже кнопкой.
- Один экземпляр API: секунды простоя на выкатке.
- Продление сертификата TURN перезапускает LiveKit раз в два месяца ночью.
- Первый прогон на реальном облаке ещё не сделан: классы хостов, TLS миграций
  Prisma и выпуск сертификата TURN написаны по документации
  (`infra/yandex-cloud/README.md`).
