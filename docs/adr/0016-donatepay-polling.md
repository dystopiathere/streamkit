# 0016. DonatePay: ключ API и опрос вместо сокета

Дата: 2026-09-25. Статус: принято.

## Контекст
DonatePay — второй донат-сервис после DonationAlerts. Проверено запросами к
боевому API и по открытому клиенту их API:

- OAuth для сторонних приложений нет. Стример копирует личный ключ на странице
  API своего кабинета (`donatepay.ru/page/api`, открывается после входа);
  ключ передаётся параметром `access_token`.
- `GET /api/v1/user` — владелец ключа (`id`, `name`, ещё баланс и выводы).
- `GET /api/v1/transactions` — транзакции с фильтрами `type`, `status`,
  `order`, `limit`, `before`, `after`, `skip`; у доната `id`, `sum` строкой,
  `status` (`success`, `wait`, `cancel`, `user`), `vars.name`,
  `vars.comment`, `created_at` — сериализованный `DateTime` PHP. Поля валюты нет.
- Отвергнутый ключ — ответ 200 с `{"status":"error","message":"Incorrect token"}`,
  без ключа — `"Empty token"`. Кодом 401 DonatePay не отвечает.
- Лимит — один запрос к методу на ключ примерно в двадцать секунд
  (`x-ratelimit-limit: 1`, дальше 429 с `retry-after`). Считается по ключу,
  а не по IP: разные ключи с одного адреса лимит не делят.
- `POST /api/v2/socket/token` существует и принимает `access_token`, сервер
  Centrifugo есть (`centrifugo.donatepay.ru`). Но формат ответа, имена каналов
  и вид сообщений описаны только в документации за входом; публично — лишь
  неофициальные клиенты, которые берут токен через виджет оповещений с CSRF.

## Решение
Подключение — ключом API: `POST /api/integrations/donations/donatepay/key`
проверяет ключ профилем и хранит его шифротекстом в `IntegrationCredential`,
как токен OAuth. В контракте у сервиса есть `connection: 'oauth' | 'api_key'`
— дашборд по нему рисует кнопку входа или поле ключа.

Донаты — опросом `transactions` из воркера (`DonatePayConnector`) раз в
двадцать секунд, через общий `ConnectorManager`:

- слот опроса на кластер — `SET NX PX` в Redis: вторая реплика воркера с тем же
  ключом упиралась бы в лимит DonatePay;
- курсор (последний разобранный донат) — в Redis: перезапуск воркера не теряет
  донаты между опросами;
- первое подключение историю не показывает: курсор встаёт на самый новый донат;
- донат в статусе `wait` держит курсор, пока не станет успешным, но не дольше
  часа — брошенная оплата не должна остановить курсор навсегда;
- донат старше десяти минут в кадр не идёт: так выглядит страница после
  простоя воркера, и без отсечки на эфир вывалилась бы пачка старых оповещений;
- дубль, всё-таки дошедший до приёма (две реплики, перезапуск), отбрасывает
  обычная дедупликация по `id` транзакции.

Валюта — рубли: DonatePay.ru принимает рубли, а поля валюты в ответе нет. Если
поле появится с незнакомой валютой, сумма считается неизвестной, как у
DonationAlerts.

## Отвергнуто
Сокет Centrifugo по догадкам. Неверное имя канала или формат сообщения не дают
ошибки — источник выглядел бы подключённым и молча не присылал бы донатов.
Когда документация сокета будет в руках (из кабинета с ключом), коннектор
меняется на подписку без изменений в контракте и дашборде: интерфейс
`DonationConnector` один для обоих способов.

## Последствия
- Оповещение о донате DonatePay приходит с задержкой до шага опроса — до
  двадцати секунд. Стример видит это в карточке сервиса.
- Больше двадцати пяти донатов между двумя опросами (размер страницы) — старшие
  из них пропускаются. Для одного стримера за двадцать секунд это за пределами
  реального.
- Донаты, пришедшие за время простоя воркера дольше десяти минут, не попадают
  ни в кадр, ни в историю.
- Проверено юнит-тестами разбора и интеграционным тестом против поддельного
  DonatePay; на живом аккаунте с донатами — ещё нет.
