# 0014. Мультичат и чат YouTube через `streamList`

Дата: 2026-09-19. Статус: принято. Отменяет раздел «Почему чата YouTube здесь
нет» в ADR 0009.

## Контекст

Стример, который ведёт эфир сразу на Twitch и YouTube, хочет видеть чат обеих
площадок одной лентой в окне эфира и выводить её в кадр. Чат Twitch уже был:
анонимный IRC, одно соединение на кластер (ADR 0009). Чата YouTube не было.
Причина — арифметика квоты: `liveChatMessages.list` стоит единицу за опрос, при
опросе раз в пять секунд шестичасовой эфир одного стримера — около 4300 единиц
из 10 000 в сутки на весь проект Google (ADR 0007).

С тех пор изменились две вещи:

- Google выпустил `liveChatMessages.streamList` — поток gRPC вместо опроса.
  Документация `list` сама советует переходить на него, потому что он «помогает
  не превысить квоту». Цена потока в таблице квот **не опубликована**.
- Квоту повышают по заявке после аудита соответствия правилам YouTube API
  Services: сервисы мультичата получали миллионы единиц в сутки.

Владелец выбрал официальный путь: API YouTube плюс заявка на повышение квоты.
Чтение внутреннего API страницы чата youtube.com квоты не тратит, но нарушает
условия YouTube и ставит под удар проверку приложения Google, на которой
держится аналитика.

## Решение

**Чат YouTube — ещё один `ChatSource`.** Единица работы — канал `UC…`, как у
Twitch; как источник его держит, менеджеру не важно. Потоки gRPC всех каналов
мультиплексируются в одном HTTP/2-соединении. Форма «одно соединение, много
каналов» из ADR 0009 сохраняется. Опрос `list` в неё не ложился — поток ложится.

**Канал проходит два состояния.** Эфира нет — источник ищет его
`liveBroadcasts.list?mine=true` (единица) не чаще раза в две минуты, пока чат
кому-то нужен. Эфир есть — открывается поток `StreamList` по `liveChatId` с
токеном стримера. `youtube.readonly`, который уже есть для аналитики, хватает;
нового разрешения Google не нужно. Эфир кончился (`offlineAt`,
`CHAT_ENDED_EVENT`, `NOT_FOUND`) — снова поиск.

**Чат читается, только пока его показывают** — как у Twitch: открыт виджет чата
в OBS или окно эфира (`PresenceService`). Виджет с выключенным YouTube его не
заказывает. У Twitch это вопрос данных третьих лиц, у YouTube вдобавок — квоты.

**Отдельный бюджет.** `QuotaService` ведёт два счётчика из одного лимита
проекта: метрики (`YOUTUBE_DAILY_QUOTA`, 7000) и чат (`YOUTUBE_CHAT_DAILY_QUOTA`,
2000). Чат одного длинного эфира не останавливает сбор метрик всем. Каждое
открытие потока резервирует `YOUTUBE_CHAT_STREAM_COST` единиц (5 — осторожная
оценка, пока цена не измерена), поиск эфира — единицу. `quotaExceeded` от Google
выравнивает оба счётчика: лимит у Google один.

**Переподключение — с `pageToken` и лесенкой пауз.** Обрыв не должен ни терять,
ни повторять сообщения, а каждое открытие потока стоит квоты: поток, который
сервер закрывает сразу, переоткрывается через 1, 2, 4… секунды до минуты, а не
раз в секунду. Первым ответом YouTube присылает историю чата — в кадр идёт
только то, что написано после подключения, как у Twitch.

**Одна аренда на все площадки** (`streamkit:owner:chat`). Вторая реплика
воркера удвоила бы сообщения, а у YouTube ещё и расход квоты.

**Состояние видно стримеру.** Воркер пишет в Redis отметку на 30 секунд:
`ok`, `waiting` (ждём эфира), `quota`, `auth`. Окно эфира подписывает каналы
этим состоянием: пустая лента YouTube без объяснения неотличима от поломки.

**Отзыв доступа — тем же путём, что у метрик.** Двойной `UNAUTHENTICATED`, а
также неудачное обновление токена переводят канал в `AUTH_EXPIRED`. Сверка
перестаёт его подключать, карточка канала просит переподключения.

## Последствия

- Цена `streamList` неизвестна до первого живого эфира. После него
  `YOUTUBE_CHAT_STREAM_COST` выставляется по графику квоты в Google Cloud Console.
- До повышения квоты чат YouTube выдержит несколько стримеров в сутки. Бюджет
  исчерпан — окно говорит «квота», чат вернётся после полуночи по
  тихоокеанскому времени. Условия (раздел 2.4) это оговаривают.
- Суперчаты, спонсорство и подарки идут тем же потоком, но это события, а не
  строки чата. Сценариями оповещений они станут отдельным решением: держать
  поток при открытом виджете оповещений значит тратить квоту не ради чата.
- Прото — выдержка из официального `stream_list.proto`, строкой в коде. Номера
  полей меняться не могут; отдельный `.proto` пришлось бы копировать в `dist`
  и не потерять в `pnpm deploy`.
- Появились обязательные ссылки YouTube API Services: Условия YouTube
  (соглашение, 2.4) и Политика Google (политика, 5.6). Их проверяет аудит квоты.
  Они были нужны и раньше, из-за аналитики.
- На время выкатки старый воркер держит ключ `…:chat:twitch`, новый —
  `…:chat`. До тридцати секунд чат Twitch может идти дважды — размен
  сознательный, ключ истекает сам.
