# 0005. Шина реального времени поверх Redis pub/sub

Дата: 2026-09-11. Статус: принято.

## Контекст
Событие может прийти на любой инстанс API или вообще в воркер, где сокет-сервера
нет. Сокет оверлея при этом висит на одном конкретном инстансе. Дополнительно:
сервис виджетов должен сообщать «конфиг изменился», а сокет-шлюзу нужен сервис
виджетов — прямая связь дала бы цикл модулей.

## Решение
Доменные события публикуются в канал Redis (`RealtimeBus`). Шлюзы подписаны на
него и рассылают своим локальным сокетам через `.local`. Socket.IO дополнительно
использует redis-adapter.

## Последствия
Событие из воркера доходит до браузера. Модули не образуют цикл: виджеты
публикуют, не зная о шлюзе. Рассылка строго локальная, поэтому одно событие не
размножается по числу инстансов.

Цена — Redis становится критичной зависимостью доставки. Потеря соединения с ним
означает, что оповещения не доходят, при работающем в остальном приложении.
Поэтому Redis входит в проверку `/readyz`.

## Замеченная ловушка
Клиент-подписчик ioredis нужно создавать с `enableReadyCheck: false`: ready-check
выполняет `INFO`, запрещённую в режиме подписки, из-за чего клиент не достигает
состояния `ready` и молча теряет подписку. Симптом — `publish` возвращает ноль
получателей без единой ошибки в логах.
