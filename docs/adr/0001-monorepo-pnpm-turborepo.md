# 0001. Монорепо на pnpm workspaces и Turborepo

Дата: 2026-09-11. Статус: принято.

## Контекст
Четыре приложения (API, воркер, дашборд, оверлей) и общие типы данных. Схема
конфига виджета нужна одновременно бэкенду для валидации, дашборду для формы
настроек и оверлею для рендера.

## Решение
Одно монорепо: `apps/*`, `packages/*`, `e2e`. pnpm workspaces для связей,
Turborepo для кэша сборки и тестов.

## Последствия
Контракт данных существует в одном экземпляре (`packages/contracts`), и
расхождение между фронтом и бэком становится ошибкой компиляции, а не багом в
проде. Цена — общий цикл релиза и необходимость собирать пакеты перед проверкой
типов приложений.

## Отвергнутые варианты
**Отдельные репозитории с генерацией типов из OpenAPI.** Проще разделять доступы,
но контракты расходятся до тех пор, пока кто-то не перегенерирует клиент.
**Nx.** Богаче инструментарий, но выше порог входа при том же результате.
