# LiveKit: медиасервер приватных комнат

Почему свой LiveKit, а не облачный, и почему оверлей подписывается на комнату, а
не получает готовую композицию, — `docs/adr/0010-private-rooms.md`.

## Локально

`compose.dev.yml` поднимает LiveKit в режиме `--dev`: встроенные ключи
`devkey` / `secret`, порты 7880, 7881/tcp и 7882/udp. В `.env` для этого
достаточно значений из `.env.example`.

## Что сделать перед выкаткой

Ничего из этого не сделано: оно зависит от домена и облака, которых у проекта
пока нет.

1. **Ключ и секрет.** Свои, секрет не короче 32 символов: LiveKit без `--dev`
   с коротким секретом не стартует. Хранятся там же, где остальные секреты
   окружения, в образы и репозиторий не попадают.
2. **TLS для сигнализации.** Браузер на https-странице не подключится к `ws://`:
   нужен `wss://rtc.<домен>` — обратный прокси с сертификатом перед портом
   7880. Этот адрес уходит в `LIVEKIT_PUBLIC_URL`.
3. **Адрес узла.** `LIVEKIT_NODE_IP` — публичный IP сервера. Ошибка в нём не
   ломает вход: участник подключается, но остаётся без видео и звука, и ни
   браузер, ни LiveKit ошибок не показывают.
4. **Порты в группе безопасности облака.** 7881/tcp и 7882/udp наружу. Порт
   7880 наружу не открывается — он за прокси с TLS.
5. **TURN на 443/tls.** Гости из корпоративных сетей и части мобильных
   операторов не пройдут ни на UDP, ни на нестандартный TCP. Встроенный TURN
   LiveKit включается в `livekit.yaml` (`turn.enabled`, домен, сертификат).
   Без него такие гости «входят» и остаются без медиа.
6. **Размер машины.** SFU только пересылает пакеты, узкое место — исходящий
   канал, а не процессор. Оценка на комнату — в ADR 0010.

## Проверка после выкатки

- Гость с телефона через мобильный интернет, Wi-Fi выключен: видео доходит до
  оверлея. Это проверка пунктов 3–5 разом.
- Оверлей в OBS с «Управлять звуком через OBS»: голос гостя виден в микшере,
  голоса стримера из оверлея нет.
