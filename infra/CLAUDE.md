# infra

## Назначение
Сборка образов и запуск окружений.

## Состав

| Файл | Для чего |
|---|---|
| `docker/compose.dev.yml` | PostgreSQL, Redis и LiveKit (`--dev`) для локальной разработки |
| `docker/compose.yml` | Полный стек: то же, что поедет в прод |
| `docker/api.Dockerfile` | Образ API и воркера — один код, разные команды |
| `docker/web.Dockerfile` | Статика дашборда и оверлея, выбор через `--build-arg APP` |
| `docker/nginx.conf` | Отдача статики |
| `docker/security-headers.conf` | Заголовки безопасности и CSP — подключаются в КАЖДЫЙ `location` со своим `add_header` |
| `docker/permissions-*.conf` | Permissions-Policy по приложению: дашборду камера и микрофон, оверлею — нет |
| `livekit/livekit.yaml` | Медиасервер комнат для `compose.yml`; что сделать перед выкаткой — `livekit/README.md` |

## Почему приложения не в dev-compose

На Windows bind-mount со структурой симлинков pnpm работает медленно и
ненадёжно, а hot-reload через контейнер добавляет секунды на каждое сохранение.
Поэтому базы — в Docker, код — на хосте. Полная сборка проверяется отдельно
через `compose.yml`, который повторяет прод.

## Правила

- Миграции выполняет отдельный одноразовый контейнер, а не старт API: при
  нескольких репликах несколько процессов начали бы мигрировать базу разом.
- Образы запускаются от непривилегированного пользователя `node`.
- `/healthz` не трогает зависимости: если упал PostgreSQL, перезапуск всех
  контейнеров API сделает только хуже. Для вывода из балансировки есть `/readyz`.
- **Заголовки проверяются `curl -I` по пути страницы**, а не чтением конфига:
  `add_header` в `location` отменяет наследование заголовков сервера, и CSP
  не доходила до страниц с первого образа, хотя в конфиге стояла.
- `VITE_*` и `CSP_CONNECT_EXTRA` вшиваются при сборке образа. Смена адреса API требует пересборки —
  это ограничение любой статики, и лучше знать о нём здесь.
- Секреты не хранятся в образах и не коммитятся. В проде — хранилище секретов
  облака, в CI — секреты GitHub.

## Запуск

```bash
docker compose -f infra/docker/compose.dev.yml --env-file .env up -d
docker compose -f infra/docker/compose.yml --env-file .env up --build
```
