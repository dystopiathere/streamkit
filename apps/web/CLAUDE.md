# @streamkit/web

## Назначение
Дашборд стримера: виджеты и их настройка, ссылки для OBS, лента событий,
источники донатов, раздел приватности.

## Технологии
React 19, Vite 8, TypeScript (strict), TanStack Query (серверное состояние),
Zustand (сессия), react-hook-form + Zod (формы), Tailwind 4, react-i18next,
socket.io-client, sonner.

## Структура

| Каталог | Что внутри |
|---|---|
| `src/lib` | `api.ts` (fetch + обновление токена), `auth-store.ts`, `query-client.ts`, `config.ts`, `i18n.ts` |
| `src/components/ui` | Примитивы интерфейса в стиле shadcn/ui |
| `src/components` | Каркас приложения, cookie-баннер |
| `src/features/widgets` | Запросы, форма настроек под тип, предпросмотр, ссылки |
| `src/features/analytics` | Метрики каналов: карточка, графики, подключение площадок |
| `src/features/privacy` | Журнал согласий: общий для раздела «Приватность» и баннера cookie |
| `src/features/rooms` | Комнаты: запросы, приглашения, сцена созвона; общая для стримера и гостя |
| `src/features/billing` | Тариф: подписка, оплата, плашка закрытых комнат |
| `src/pages` | Страницы, по одной на маршрут |
| `public/legal` | Тексты юридических документов (статика) |

## Ключевые решения

**Access-токен только в памяти.** Ни `localStorage`, ни `sessionStorage`: оба
читаются любым скриптом на странице. Цена — потеря сессии при перезагрузке
вкладки, она восстанавливается обменом httpOnly-cookie на новый токен при старте.

**Обновление токена кэшируется одним промисом.** При загрузке страницы уходит
несколько запросов сразу; без кэша каждый 401 запустил бы свой `/auth/refresh`, а
параллельные обновления сервер справедливо считает переиспользованием токена и
разлогинивает пользователя.

**Два разных адреса бэкенда.** `API_BASE` — с префиксом `/api`, `SOCKET_URL` —
origin без префикса. Их легко перепутать, и ошибка проявляется только в собранном
бандле (в разработке спасает прокси Vite). Оба заданы в `src/lib/config.ts`.

**Компоненты интерфейса скопированы, а не подключены зависимостью** — подход
shadcn/ui. Структура совместима с `npx shadcn@latest add <component>`, так что
недостающие примитивы добавляются командой.

**Предпросмотр виджета использует тот же рендерер, что и overlay**
(`@streamkit/ui`). Иначе расхождение «в редакторе одно, на стриме другое» — лишь
вопрос времени.

**Форма настроек выбирается по типу виджета, а не по маршруту.** Обвязка
редактора (имя, предпросмотр, ссылки OBS, сохранение) у всех типов одна,
различается только набор полей; схема валидации берётся из `configSchemaFor`.
Поля формы обобщены по типу формы намеренно — иначе `valueAsNumber` пришлось бы
повторить в четырёх местах.

**Управление состоянием отделено от формы настроек.** Настройки применяются по
кнопке «Сохранить», а «запустить таймер» действует немедленно и видно зрителям.
В одной форме это означало бы запуск марафона случайным нажатием Enter.

## Правила

- **Импорты между папками — через алиас `@/`**, а не через `../`. Алиас объявлен
  трижды: в `tsconfig.json`, `vite.config.ts` и `vitest.config.ts` — у tsc, vite
  и vitest независимые резолверы, и забытый третий проявляется только в тестах.
  Соседние файлы (`./`) остаются относительными.
- Весь текст интерфейса — через `t('ключ')`, даже пока локаль одна. Вынести сотни
  зашитых строк потом заметно дороже.
- Серверное состояние живёт в TanStack Query, клиентское — в локальном состоянии
  компонента. Zustand только для сессии.
- Числовые поля формы регистрируются с `valueAsNumber: true`, иначе в Zod уедет
  строка и форма отвергнется с невнятной ошибкой.
- Аналитика не инициализируется, пока пользователь не согласился в cookie-баннере.
- **Согласие на cookie живёт в журнале на сервере**, в localStorage — только его
  копия (`lib/cookie-consent.ts`). Незаписанное в журнал «Принять все» согласием
  не считается: баннер спросит снова.
- **Перед кодом графиков читается скилл `dataviz`**, а палитра проверяется его
  валидатором. Две оси на одном графике запрещены; цвета рядов подобраны с
  проверкой на дальтонизм, зелёный и красный зарезервированы под статусы.
- Маршрут аналитики грузится через `React.lazy`: только он тянет библиотеку
  графиков, а это больше трети бандла. Так же — комната стримера и страница
  гостя: клиент WebRTC весит больше всего остального дашборда.
- **Кэш запросов чистится при выходе и при смене пользователя**
  (`auth-store.ts`). Он принадлежит пользователю, а не вкладке.
- **Страница гостя `/join` — вне `RequireAuth`.** Токен приглашения во
  фрагменте адреса: фрагмент не уходит на сервер и не оседает в журналах.
- **Колбэки и опции для хуков LiveKit стабильны** (`useCallback`, `useMemo`,
  `ROOM_OPTIONS`): новый объект на каждый рендер перезапускает их эффекты —
  камера пересоздаётся, комната переподключается.
- **Микрофон и камеру в комнате публикует сцена** (`useMicrophone`, `useCamera`),
  а не `audio`/`video` у `LiveKitRoom`. Микрофон — с выбранной обработкой голоса
  (`microphone-processing.ts`): она хранится в localStorage, потому что описывает
  микрофон этого компьютера, а у гостя нет аккаунта. Смена качества передачи
  публикует дорожку заново, выключенный микрофон при этом не открывается.
- **Данные карты в дашборд не попадают.** «Оплатить» уводит на страницу
  ЮKassa, возврат — `/billing?payment=<id>` с опросом платежа не дольше минуты.
- Согласие на автоматические списания показывает сумму и периодичность прямо
  в тексте флажка, а не только в оферте по ссылке.
- Кнопка отказа в баннере равнозначна кнопке согласия по виду и расположению.

## Проверка

```bash
pnpm --filter @streamkit/web dev      # нужен запущенный API на :3000
pnpm --filter @streamkit/web build    # включает проверку типов
```

## Известные ограничения

- Основной бандл ~440 КБ, аналитика вынесена отдельным чанком на ~373 КБ, клиент
  комнат — на ~572 КБ. Остальные маршруты по-прежнему в основном чанке.
- После выключения камера остаётся открытой полминуты (`CAMERA_RELEASE_MS`):
  повторное включение мгновенное, но индикатор камеры это время горит, хотя
  видео никуда не уходит.
- Сцена созвона без индикатора говорящего и без выбора устройств после входа:
  микрофон и камера выбираются на странице гостя до входа, у стримера — системные.
- Юридические документы выводятся моноширинным текстом без разметки Markdown:
  для дословного юридического текста это осознанный компромисс, рендерер добавим
  при необходимости.
- Нет страницы настроек безопасности (смена пароля, 2FA, список сессий) — API для
  них готов, интерфейса пока нет.
