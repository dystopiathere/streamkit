# @streamkit/web

## Назначение
Дашборд стримера: виджеты и их настройка, ссылки для OBS, лента событий,
источники донатов, раздел приватности.

## Технологии
React 19, Vite 8, TypeScript (strict), TanStack Query (серверное состояние),
Zustand (сессия), react-hook-form + Zod (формы), Tailwind 4, react-i18next,
socket.io-client, sonner, react-markdown + remark-gfm (юридические документы).

## Структура

| Каталог | Что внутри |
|---|---|
| `src/lib` | `api.ts` (клиент из app-kit с путём обновления дашборда), `auth-store.ts`, `query-client.ts`, `config.ts`, `i18n.ts` (определение языка), `locale.ts` (язык, форматы, переключение), `form-errors.ts` |
| `@streamkit/app-kit` | Примитивы, каркас страницы, таблицы, диалог и клиент API — общие с админкой (`packages/app-kit`) |
| `src/components` | Каркас приложения и cookie-баннер |
| `src/features/widgets` | Запросы, форма настроек под тип, предпросмотр, ссылки |
| `src/features/analytics` | Метрики каналов: карточка, графики, подключение площадок |
| `src/features/auth` | Двухфакторный вход: включение по QR-коду и выключение по паролю |
| `src/features/sources` | Источники донатов: подключение DonationAlerts, вебхук для разработчиков |
| `src/features/privacy` | Журнал согласий: общий для раздела «Приватность» и баннера cookie |
| `src/features/rooms` | Комнаты: запросы, приглашения, сцена созвона; общая для стримера и гостя |
| `src/features/billing` | Тариф: подписка, оплата, плашка закрытых комнат |
| `src/features/public` | Публичная часть: реквизиты продавца, подвал, подстановка в документы |
| `src/pages` | Страницы, по одной на маршрут |
| `public/legal` | Тексты юридических документов (статика); `en/` — английские переводы |

## Ключевые решения

**Access-токен только в памяти.** Ни `localStorage`, ни `sessionStorage`: оба
читаются любым скриптом на странице. Цена — потеря сессии при перезагрузке
вкладки, она восстанавливается обменом httpOnly-cookie на новый токен при старте.

**Обновление токена кэшируется одним промисом и идёт под `navigator.locks`.**
При загрузке страницы уходит несколько запросов сразу; без кэша каждый 401
запустил бы свой `/auth/refresh`, а параллельные обновления сервер справедливо
считает переиспользованием токена и разлогинивает пользователя. Промис живёт в
вкладке, блокировка — между вкладками. Разлогинивает только 401/403 на refresh:
429 и 5xx — это «не сейчас», а не «сессии нет».

**Два разных адреса бэкенда.** `API_BASE` — с префиксом `/api`, `SOCKET_URL` —
origin без префикса. Их легко перепутать, и ошибка проявляется только в собранном
бандле (в разработке спасает прокси Vite). Оба заданы в `src/lib/config.ts`.

**Компоненты интерфейса скопированы, а не подключены зависимостью** — подход
shadcn/ui. Структура совместима с `npx shadcn@latest add <component>`, так что
недостающие примитивы добавляются командой.

**Предпросмотр виджета использует тот же рендерер, что и overlay**
(`@streamkit/ui`). Иначе расхождение «в редакторе одно, на стриме другое» — лишь
вопрос времени.

**Форма настроек выбирается по типу виджета, а не по маршруту.** Обвязка
редактора (имя, предпросмотр, ссылки OBS, сохранение) у всех типов одна,
различается только набор полей; схема валидации берётся из `configSchemaFor`.
Поля формы обобщены по типу формы намеренно — иначе `valueAsNumber` пришлось бы
повторить в четырёх местах.

**Управление состоянием отделено от формы настроек.** Настройки применяются по
кнопке «Сохранить», а «запустить таймер» действует немедленно и видно зрителям.
В одной форме это означало бы запуск марафона случайным нажатием Enter.

## Правила

- **Импорты между папками — через алиас `@/`**, а не через `../`. Алиас объявлен
  трижды: в `tsconfig.json`, `vite.config.ts` и `vitest.config.ts` — у tsc, vite
  и vitest независимые резолверы, и забытый третий проявляется только в тестах.
  Соседние файлы (`./`) остаются относительными.
- Весь текст интерфейса — через `t('ключ')`, в двух словарях: `ru.json` и
  `en.json`. Ключи и переменные у них совпадают — это проверяет
  `locales.test.ts`. Английские множественные формы — `_one` и `_other`.
- **Язык** — `?lang=`, потом выбор переключателем (`streamkit.language` в
  localStorage), потом язык браузера, иначе русский (`lib/i18n.ts`). Даты,
  числа и суммы — через `intlLocale()` и `formatMoney` из `lib/locale.ts`, не
  `'ru-RU'` и не `formatMoney` из contracts напрямую.
- **Рендереры виджетов (`@streamkit/ui`) не переводятся**: предпросмотр обязан
  совпадать с OBS. На языке дашборда только примеры в предпросмотре и то, что
  пишется в кадр при создании: заголовки цели и топа, тестовый алерт.
- **Ошибки API и схем форм приходят по-русски** и переводятся словарём
  `MESSAGES_EN` (contracts) в `lib/api.ts` и `localizedResolver`. Новая форма с
  `zodResolver` оборачивается в `localizedResolver`.
- Серверное состояние живёт в TanStack Query, клиентское — в локальном состоянии
  компонента. Zustand только для сессии.
- Числовые поля формы регистрируются с `valueAsNumber: true`, иначе в Zod уедет
  строка и форма отвергнется с невнятной ошибкой.
- **Статистика посещений (Umami) не грузится без согласия и считает только
  публичные страницы** (`features/public/site-stats.ts`, `isTrackedPath`).
  Дашборд, комнаты и `/join` не считаются никогда: там донаты, почта и токены в
  адресе. Скрипт и события — через свой домен по префиксу `/u`, из адресов
  уходят только путь и `utm_*`.
- **Баннер cookie смонтирован в корне приложения** и работает в двух режимах:
  у вошедшего согласие пишется в его журнал, у посетителя — в журнал
  посетителей со случайным `streamkit.visitor-id`. Выход стирает копию выбора.
- **Согласие на cookie живёт в журнале на сервере**, в localStorage — только его
  копия (`lib/cookie-consent.ts`). Незаписанное в журнал «Принять все» согласием
  не считается: баннер спросит снова.
- **Перед кодом графиков читается скилл `dataviz`**, а палитра проверяется его
  валидатором. Две оси на одном графике запрещены; цвета рядов подобраны с
  проверкой на дальтонизм, зелёный и красный зарезервированы под статусы.
- Маршрут аналитики грузится через `React.lazy`: только он тянет библиотеку
  графиков, а это больше трети бандла. Так же — комната стримера и страница
  гостя: клиент WebRTC весит больше всего остального дашборда.
- **Кэш запросов чистится при выходе и при смене пользователя**
  (`auth-store.ts`). Он принадлежит пользователю, а не вкладке.
- **Страница гостя `/join` — вне `RequireAuth`.** Токен приглашения во
  фрагменте адреса: фрагмент не уходит на сервер и не оседает в журналах.
- **Колбэки и опции для хуков LiveKit стабильны** (`useCallback`, `useMemo`,
  `ROOM_OPTIONS`): новый объект на каждый рендер перезапускает их эффекты —
  камера пересоздаётся, комната переподключается.
- **Микрофон и камеру в комнате публикует сцена** (`useMicrophone`, `useCamera`),
  а не `audio`/`video` у `LiveKitRoom`. Микрофон — с выбранной обработкой голоса
  (`microphone-processing.ts`): она хранится в localStorage, потому что описывает
  микрофон этого компьютера, а у гостя нет аккаунта. Смена качества передачи
  публикует дорожку заново, выключенный микрофон при этом не открывается.
- **Данные карты в дашборд не попадают.** «Оплатить» уводит на страницу
  ЮKassa, возврат — `/billing?payment=<id>` с опросом платежа не дольше минуты.
- Согласие на автоматические списания показывает сумму и периодичность прямо
  в тексте флажка, а не только в оферте по ссылке.
- **Корень сайта — публичная главная** (`LandingPage`), не редирект в дашборд.
  Её и подвал с документами и реквизитами проверяет ЮKassa до подключения оплаты;
  подвал стоит на всех страницах без входа (`PublicFooter`).
- **Реквизиты продавца и цены в документах — метками** (`{{SELLER_INN}}`,
  `{{PRICE_MONTH}}`), подставляет `fillDocumentDetails`. Вписывать ИНН или цену
  в текст документа руками нельзя: первое — персональные данные в репозитории,
  второе разойдётся с `PLAN_PRICES`.
- Кнопка отказа в баннере равнозначна кнопке согласия по виду и расположению.
- **Шапка сворачивается в меню на узком экране** (`useCollapsibleMenu`,
  `MenuButton`): дашборд — ниже `lg`, главная — ниже `sm`, причём вход на
  главной виден всегда. Меню — один и тот же `<nav>`, который CSS показывает
  строкой или столбцом, а не две копии ссылок.
- **Двухфакторный вход включается в «Приватности»** (`features/auth`). Без него
  сотрудник не войдёт в админку. Экрана не было, хотя API было готово: сквозной
  тест включал второй фактор запросом, и пробел нашёл первый админ на проде.
- **Итог мутации, которая меняет саму форму, сообщается в хуке, а не колбэком
  `mutate`.** Колбэки `mutate` у размонтированного компонента TanStack Query не
  вызывает: после включения 2FA форма включения сменяется формой выключения, и
  уведомление «включён» молча пропадало.
- **Юридические документы рендерятся из Markdown** (`LegalPage`,
  `react-markdown` без сырого HTML). Реквизиты подставляются с
  `escapeMarkdown`: иначе звёздочка в названии продавца стала бы курсивом.

### Доступность

Проверяется при каждой правке разметки, а не отдельным этапом.

- **Ссылка, похожая на кнопку, — `ButtonLink`**, а не `<Button>` внутри
  `<Link>`: кнопка внутри ссылки — недопустимая разметка и две остановки Tab.
- **Курсор задан в теме `app-kit` для всего кликабельного.** Tailwind 4 вернул
  кнопкам стрелку; утилиту `cursor-pointer` по элементам не раскладывать.
- **У каждого поля есть подпись**: `<Label htmlFor>`, а если подписи на экране
  нет — `aria-label`. Placeholder подписью не считается. Подсказка и ошибка
  связаны с полем через `describeField`, `FieldHint`, `FieldError id`.
- **Кнопка в строке списка называет свой объект**: «Удалить «Имя»» в
  `aria-label`, начинаясь с видимого текста кнопки (WCAG 2.5.3). Иначе
  скринридер зачитывает пять одинаковых «Удалить».
- **Состояние передаётся текстом или формой, не только цветом.** Ошибки —
  `role="alert"`, загрузка и итог действия — `role="status"`, живая лента —
  `aria-live`.
- **У страницы свой заголовок вкладки** (`usePageTitle`), а содержимое — в
  `MainContent`: туда ведёт ссылка «Перейти к содержимому» и туда переносится фокус
  после перехода.
- **Графики продублированы текстом** (`useChartSummary`): подсказка графика
  появляется только при наведении мыши.
- **Цвета — только из токенов темы**, контраст которых посчитан (комментарий в
  `packages/app-kit/src/theme.css`). `danger` — для текста, `danger-strong` — для фона кнопки;
  рамка полей — `border-strong`, обычный `border` — только разделители.
- Ссылка в новую вкладку несёт `<NewTabHint />`.

```bash

```

## Известные ограничения

- Основной бандл ~440 КБ плюс общий чанк ~230 КБ; аналитика — отдельным чанком
  на ~373 КБ, клиент комнат — на ~580 КБ, документы с рендером Markdown — на
  ~160 КБ. Остальные маршруты по-прежнему в основном чанке.
- После выключения камера остаётся открытой полминуты (`CAMERA_RELEASE_MS`):
  повторное включение мгновенное, но индикатор камеры это время горит, хотя
  видео никуда не уходит.
- Сцена созвона без индикатора говорящего и без выбора устройств после входа:
  микрофон и камера выбираются на странице гостя до входа, у стримера — системные.
- Доступность проверена разбором разметки, расчётом контраста и сквозными
  тестами по ролям; живым скринридером (NVDA, TalkBack) интерфейс не проходили.
- Подтверждения удаления — `window.confirm`: доступно, но выглядит чужеродно.
- Из настроек безопасности есть только двухфакторный вход (карточка в
  «Приватности»). Смены пароля и списка сессий в интерфейсе нет, хотя API для них
  готов.
