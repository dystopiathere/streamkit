# Модуль analytics

## Назначение
Сбор и показ метрик подключённых площадок: число зрителей в эфире, подписчики,
фолловеры, часы в эфире. Контроллер работает в API, опрос — в воркере.

## Устройство

| Файл | Что делает |
|---|---|
| `analytics.service.ts` | Чтение: список каналов, сводка, ряд, суммы донатов |
| `analytics.controller.ts` | `GET /channels`, `/channels/:id/summary`, `/channels/:id/series`, `DELETE /channels/:id`, `GET /analytics/donations` |
| `analytics-poller.service.ts` | Один проход опроса: выбор каналов, запрос метрик, запись снимка |
| `analytics.module.ts` | Модуль плюс `AnalyticsScheduler` — он подключается только воркером |
| `quota.service.ts` | Учёт суточного бюджета запросов к внешнему API |

Провайдеры площадок живут в соседнем `modules/integrations`: там же OAuth и
хранение токенов, потому что они общие с коннекторами донатов.

## Ключевые решения

**Хранятся сырые снимки, а не предагрегаты.** Диапазоны в интерфейсе будут
меняться; пересчитать агрегат из снимков можно, восстановить снимки из
агрегата — нет. Прореживание до читаемого числа точек делает SQL-запрос
(`date_trunc` по часу или суткам), а не приложение: месяц минутных снимков это
под сорок тысяч строк.

**Каденция адаптивная и продиктована квотой, а не «скоростью изменений».**
В эфире раз в минуту, вне эфира раз в пятнадцать минут. Минутный опрос круглые
сутки стоил бы 4320 единиц YouTube на один канал при суточном лимите 10 000
**на весь проект**. Пятнадцать минут дают 288 — примерно тридцать каналов на
инсталляцию.

**Бюджет резервируется ДО запроса.** Списание после означало бы, что превышение
обнаруживается уже потраченным. Google не сообщает остаток квоты в ответах:
узнать об исчерпании можно только получив 403 `quotaExceeded`. Сутки квоты —
по тихоокеанскому времени, как у Google (`quotaKey`, `nextQuotaReset`):
считая их по UTC, опрос после исчерпания простаивал лишние шестнадцать часов.

**Время в эфире восстанавливается по промежуткам между снимками.** Длительность
нигде не записана — записаны отдельные моменты. Промежутки длиннее пяти минут
обрезаются: это перерыв в опросе, а не длинный стрим.

**`null` не заменяется нулём нигде.** Вне эфира зрителей не «ноль», а
«неизвестно»; скрытый счётчик подписчиков YouTube — тоже. Ноль на графике
читается как обвал, которого не было.

**Состояние канала — отдельное поле, а не строка ошибки.** «Переподключите
площадку», «квота исчерпана» и «попробуем позже» ведут к трём разным действиям
пользователя. `syncError` наружу не отдаётся — только в логи.

## Правила

- Владение каналом проверяется в каждом методе; чужой канал отдаёт 404.
- `AVG`/`MAX`/`date_trunc` считает СУБД. Вытаскивать ряд в память, чтобы отдать
  тридцать точек, нельзя.
- Донаты считаются по пользователю, НЕ по каналу: они приходят из
  DonationAlerts и вебхука, которые про канал площадки ничего не знают.
- Опрос по расписанию обязан идти под `RedisLock`: расписание живёт в каждой
  реплике воркера, а квота общая.
- Новая площадка = класс по `PlatformProvider` плюс строка в `PlatformRegistry`.
  Здесь ничего менять не нужно.

## Проверка

```bash
pnpm --filter @streamkit/api test        # каденция, квота, нормализация ответов
pnpm --filter @streamkit/api test:int    # дельты, прореживание, 404, OAuth-состояние
```

## Известные ограничения

- Коннектор Twitch написан по спецификации Helix и **не проверен на живом
  аккаунте**: приложение Twitch пока не зарегистрировано. YouTube проверен.
- Снимки хранятся 90 дней, дальше их удаляет ночная уборка. Срок заявлен в
  политике обработки ПДн и обязан совпадать с ней.
- `liveBroadcasts.list` показывает только трансляции, заведённые через Live
  Control Room. Эфир, поднятый иначе, будет числиться офлайн.
